# Reflection on Development Process (WeatherWise / Weather Advisor)

This assignment helped me integrate core Python skills with intentional AI prompting to build a practical weather application. I began by restating the problem and identifying the required functions, data flows, and user experience. I chose the wttr.in JSON API because it is simple, reliable, and requires no API key. This supported rapid iteration while still demonstrating API skills. I designed the project using a modular structure: `weather_data.py` for retrieval, `nlp.py` for parsing questions, `visuals.py` for charts, and `ui.py` for the console menu and responses. This separation of concerns kept each file focused and easier to test.

I used AI deliberately at several stages. First, I asked for a comparison of data sources (fetch‑my‑weather, wttr.in, OpenWeatherMap) and discussed trade‑offs around reliability, customisation, and bonus marks. Second, I requested I/O specifications and pseudocode for the three core functions so I understood the interfaces before coding. Third, I challenged edge cases such as invalid locations, network timeouts, and missing hourly data; AI helped me plan defensive programming and a mock fallback. Fourth, I requested iterative improvements to early code—adding docstrings, clamping forecast days to 1–5, and turning ambiguous returns into explicit error messages. Finally, I asked for explanations of the design so I could justify decisions in my documentation.

The most valuable part was learning to treat AI as a collaborator rather than an answer generator. By restating the problem, constraining outputs, and challenging failure modes, I received higher‑quality suggestions and avoided blindly copying code. I documented five conversation logs showing the journey, including one where I detected an incorrect assumption and asked the AI to correct it. This process improved my debugging skills and my confidence in evaluating AI output.

From a technical perspective, I practiced requests handling, JSON parsing, and Matplotlib visualisations. I implemented two charts—temperature trend and precipitation probability—that read from the same processed data structure. The menu uses `pyinputplus` for robust inputs and routes all requests through the core functions to avoid duplication. For offline testing I included a small realistic mock dataset that exercises the UI and charts without external calls.

Version control on GitHub recorded meaningful commits during planning, feature development, refactoring, and polishing. Overall, this project strengthened my ability to build a complete Python application and to use AI intentionally, critically, and transparently.
